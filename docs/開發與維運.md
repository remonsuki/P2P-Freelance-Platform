# YunBarter 開發與維運

本文件涵蓋團隊資料庫、前端部署，以及登入、預約與鏈上交易的開發參考。本機啟動方式見[專案 README](../README.md)。

## 團隊共用 PostgreSQL

各組員可各自執行前端與後端，並將 Express 後端連到同一座 PostgreSQL 開發庫，共用會員、課程和預約。程式碼、遷移和初始資料透過 Git 同步。連線憑證存於各自的 `yunbarter-backend/.env`，本機資料庫備份存於 `.local-backups/`。

後端使用已設定的 `DATABASE_URL`，其次才讀取 `PGHOST`、`PGPORT`、`PGDATABASE`、`PGUSER`、`PGPASSWORD`。同一個變數以程序環境為優先，其次是 `.env.chain.local`，最後是 `.env`。切換資料庫前請核對這三處，並在採用 `PG*` 設定時清除原有的 `DATABASE_URL`。

### 雲端開發庫（Neon）

1. 建立獨立的開發庫，例如在 Neon 建立 `yunbarter_team` 專案。連線所需的資料庫名稱可在 Neon Connect 畫面確認。由資料表擁有者在 `yunbarter-backend` 執行 `npm run db:migrate`，需要初始資料時對空庫執行一次 `npm run db:seed`。[Neon 方案與用量](https://neon.com/pricing)
2. 透過私下管道交付含 TLS 設定的連線字串。可為各組員建立獨立的 PostgreSQL 登入角色，並授予日常執行後端所需的讀寫權限。
3. 各組員在 `yunbarter-backend/.env` 設定 `DATABASE_URL`，執行 `npm start`，並開啟 `http://localhost:5000/api/health` 確認連線。可由一位組員新增課程，另一位重新整理課程列表確認共用結果。
4. 有新遷移時，先同步 `main`，再由資料庫負責人更新共用庫。

要搬移既有資料時，用 `pg_dump` 匯出可共用的測試或去識別化資料，排除登入 Session 和一次性錢包驗證資料。還原到新空庫後執行 `npm run db:migrate`。最後一次匯出與切換連線期間可暫停寫入，避免漏掉切換過程中的新增或更新。[Neon 匯入指南](https://neon.com/docs/import/migrate-from-postgres)

### 共用 Windows 主機（Tailscale）

此方式使用主機上的 `yunbarter` 資料庫。主機須保持開機，並執行 PostgreSQL 和 Tailscale。

1. 主機登入 Tailscale，透過單次邀請逐一分享給指定組員。存取政策僅授權受邀者連線至主機的 `15432/TCP`，並檢查其他政策的存取範圍。[Tailscale 裝置分享](https://tailscale.com/docs/features/sharing) · [Tailscale 存取規則](https://tailscale.com/docs/features/access-control/grants)
2. 主機在 PowerShell 執行以下指令，將私有網路的 `15432/TCP` 轉送到本機 PostgreSQL 的 `5432`。[Tailscale Serve 指令](https://tailscale.com/docs/reference/tailscale-cli/serve)

   ```powershell
   tailscale serve --bg --tcp=15432 tcp://127.0.0.1:5432
   tailscale serve status
   ```

3. 主機私下交付各組員自己的 PostgreSQL 帳號。組員在後端 `.env` 設定下列資料，也可用相同資訊在 pgAdmin 建立連線。

   | 變數 | 設定值 |
   | --- | --- |
   | `PGHOST` | 主機的 Tailscale IP |
   | `PGPORT` | `15432` |
   | `PGDATABASE` | `yunbarter` |
   | `PGUSER`、`PGPASSWORD` | 組員各自的 PostgreSQL 帳號和密碼 |

4. 在 `yunbarter-backend` 執行 `npm start`，開啟 `http://localhost:5000/api/health` 確認連線。共用庫的遷移由主機管理者執行，新增資料表或序列後，管理者需授予 `yunbarter_team_access` 對應的權限。
5. 結束分享時在主機執行 `tailscale serve --bg --tcp=15432 off`。只停用單一組員時，可撤銷該組員的裝置分享並停用對應的 PostgreSQL 登入角色。

若團隊僅需同步表結構與初始開發資料，各組員可建立自己的本機資料庫，再依序執行 `npm run db:migrate` 和 `npm run db:seed`。[PostgreSQL 初次使用](PostgreSQL-初次使用.md)

## 前端部署與 Cookie

| 情境 | 設定 |
| --- | --- |
| 本機開發 | Vite 預設為 `http://localhost:5173`。前端預設呼叫同主機的 `5000` port。請讓兩端採用相同主機名稱。 |
| 自訂前端網址或 port | 將前端完整來源（協定、主機名稱及 port）加入後端 `FRONTEND_ORIGINS`。多個來源以逗號分隔。 |
| 正式部署 | 使用 HTTPS，並將同站的 `/api` 反向代理至後端。後端設定 `NODE_ENV=production` 後會啟用 Secure Cookie。 |
| 獨立的 API 網址 | 在前端 `.env.local` 設定 `VITE_API_BASE_URL`，例如 `https://api.example.com`。前端會在基本網址後加上 `/api` 路徑。 |

前端請求由瀏覽器帶入 Session Cookie。Cookie 採 `HttpOnly` 與 `SameSite=Lax`，因此前端與 API 應部署在同一 site。自訂 API 網址時也要設定對應的 `FRONTEND_ORIGINS`。

## AI 課程草稿

在 `yunbarter-backend/.env` 設定 `GEMINI_API_KEY` 後重新啟動後端，預設使用具免費額度的 `gemini-3.1-flash-lite`。可用 `GEMINI_MODEL` 指定其他支援結構化輸出的模型。若使用 OpenAI，可改設定 `OPENAI_API_KEY`，預設使用 `gpt-5.4-mini`。兩種金鑰都已設定時，後端優先使用 Gemini。[Gemini 金鑰管理](https://aistudio.google.com/docs/api-key) · [Gemini 免費及付費額度](https://aistudio.google.com/docs/pricing)

發布頁只需輸入課程名稱即可生成課名、詳細說明、技能類別與 SKILL 建議定價。已有的說明和選用的語氣可供 AI 參考。定價會先比對所選類別的上架課程，再依可用樣本擴大參考範圍。全站沒有樣本時，AI 會給出起始建議。發布前可以修改所有欄位。

## 登入與權限

- 會員以電子郵件及密碼登入。登入會輪替同一瀏覽器的 Session，登出會撤銷該 Session，同一瀏覽器的分頁共用登入狀態。資料庫儲存隨機 Session Token 的 SHA-256 雜湊，有效期預設為 168 小時，可用 `SESSION_TTL_HOURS` 調整。
- 新帳號的密碼至少 8 個字元。註冊先在 MetaMask 完成一次性簽章，再於同一資料庫交易建立帳號、綁定錢包及簽發 Session。
- 會員與錢包永久一對一綁定。綁定地址儲存在 `users.verified_wallet_address`，由唯一索引和觸發器保護。尚未綁定的既有會員可用電子郵件登入，在錢包頁完成一次補綁。綁定可在 SKILL 付款停用時執行。
- 個人檔案、錢包與課程異動需登入，否則回傳 `401`。課程只有擁有者能編輯或下架，其他會員收到 `403`。仍有進行中預約或鏈上託管的課程須先處理相關交易。

## 課程、排班與預約

- `courses` 儲存課程內容，`teacher_availability` 儲存老師共用排班，`classes` 儲存各堂課的場次。預約保存建立當時的課名及成交金額，課程後續編輯與下架仍保留這些紀錄。
- 排班以 `Asia/Taipei` 為準，時段為 09:00–10:00、14:00–15:00、19:00–20:00。已有人預約的時段須保留，清空排班表示暫停接受預約。
- 預約、錢包和課程畫面在完成操作、切回視窗和可見期間每 15 秒重新讀取資料。
- 更新資料庫結構時，在後端執行 `npm run db:migrate`，再重啟後端與前端。遷移會在資料庫交易內套用尚未執行的版本，並將既有明碼密碼轉為加鹽 scrypt 雜湊。舊資料若有大小寫正規化後重複的信箱或錢包地址，請先處理重複資料，再執行遷移。

## 鏈上交易開發參考

平台以 SKILL 付款，前端透過 MetaMask 讀取 SKILL 和 ETH 餘額。後端核對報價、合約狀態、事件及收據並等待確認後，才同步預約及備份交易。舊 YTC 紀錄封存供查閱，舊點數異動 API 回傳 `410`。Sepolia 設定、合約部署及結算流程見[SKILL 鏈上交易與部署](SKILL-交易與部署.md)。

| API | 用途 |
| --- | --- |
| `GET /api/bookings` | 讀取登入者參與的預約，涵蓋學生和老師兩種身分。 |
| `POST /api/chain/quotes` | 依學生、老師、時段及 SKILL 金額產生簽章報價。 |
| `POST /api/chain/payments/:id/sync` | 使用 MetaMask 完成授權與託管付款，或完成結算後，用於核對鏈上結果。 |
| `GET /api/chain/transactions` | 讀取已確認的交易備份並同步錢包事件。RPC 暫停期間可讀取已備份資料。 |
| `POST /api/chain/transactions/sync` | 傳入交易雜湊提示，由後端核對鏈上收據並備份。 |

後端可重複執行 `npm run db:sync-chain` 補齊既有付款各階段及錢包的授權、轉帳紀錄。早期 Ganache 驗收報告若存在，可在 `.local-backups/chain-test/` 查閱。
